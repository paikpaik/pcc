pcc 구조 가이드

개인 전용 Claude Code 플러그인. ECC의 agents / skills / commands / hooks / rules 아키텍처 패턴만 참고해서, 실제로 쓰는 만큼만 가볍게 채워가고 있습니다. 이 문서는 지금까지 만든 뼈대를 한눈에 파악하기 위한 참고용 가이드입니다.

현재 구조

.claude-plugin/plugin.json 작성됨

플러그인 매니페스트. name, version, commands/skills 경로(배열), mcpServers: {} 를 포함.

agents/ 비어있음

특화된 서브에이전트(마크다운 + YAML frontmatter). 아직 없음 — .gitkeep만 존재.

skills/ 비어있음

재사용 가능한 워크플로우/도메인 지식. skills/<name>/SKILL.md 형태로 추가 예정.

commands/ 비어있음

슬래시 명령어. 아직 없음 — .gitkeep만 존재.

hooks/ 비어있음

라이프사이클 자동화. hooks/hooks.json을 두면 Claude Code v2.1+가 컨벤션으로 자동 로드.

rules/ 비어있음

언어/도메인별 always-load 규칙. 주력 스택: TypeScript/JavaScript, Python.

repo/ECC 참고용

ECC 원본 클론. .gitignore에 등록되어 pcc git 추적 대상이 아님 — 형식/패턴 참고 전용.

각 컴포넌트 역할

디렉토리역할파일 형식
agents/ 특정 작업에 특화된 서브에이전트 (예: 코드 리뷰어, 아키텍트) MD + YAML frontmatter (name, description, tools, model)
skills/ 재사용 가능한 워크플로우/도메인 지식 묶음 skills/<name>/SKILL.md
commands/ 사용자가 직접 호출하는 슬래시 명령어 MD + description: frontmatter
hooks/ 세션 시작/종료, pre/post-tool 등 라이프사이클 자동화 hooks.json (matcher + command)
rules/ 항상 로드되는 언어별/보안/테스트 상시 규칙 언어별 하위 디렉토리 + MD

플러그인 매니페스트 함정

ECC의 PLUGIN_SCHEMA_NOTES.md에서 확인된, 문서화되지 않았지만 실제로 강제되는 검증기 제약입니다.

agents 필드를 plugin.json에 추가하지 말 것 매니페스트 스키마에 없는 필드라 agents: Invalid input 오류로 검증 실패. agents/*.md는 컨벤션으로 자동 인식됨.
hooks 필드를 plugin.json에 추가하지 말 것 hooks/hooks.json은 자동 로드되므로, 명시적으로 선언하면 "Duplicate hooks file detected" 오류 발생.
commands, skills 필드는 항상 배열 값이 하나뿐이어도 문자열이 아니라 배열로 감싸야 함 (["./commands/"]).
version 필드 필수 누락 시 마켓플레이스 설치 또는 CLI 검증 단계에서 실패할 수 있음.

검증 명령어

claude plugin validate .claude-plugin/plugin.json

다음 단계 로드맵

처음부터 다 채우지 않고, 실제로 쓰면서 필요한 것부터 하나씩 추가하는 중입니다.

  1. agent 또는 command 하나로 패턴 검증 가장 자주 반복하는 작업(예: 코드 리뷰, 빌드 오류 수정) 하나를 골라 형식을 검증한다.
  2. rules/typescript, rules/python 기본 규칙 작성 주력 스택 기준으로 항상 지켜야 할 코딩 스타일/테스트 규칙을 최소한으로 정리.
  3. 필요할 때 skill 추가 같은 워크플로우를 두 번 이상 반복하게 되면 그때 skill로 승격.
  4. hooks는 자동화가 명확히 필요할 때만 세션 요약, 포맷 검사 등 실제로 아쉬웠던 지점이 생기면 추가.
